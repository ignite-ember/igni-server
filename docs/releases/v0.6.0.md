# igni server 0.6.0

**This release was never tagged and never built.** It was prepared — the
version was set, the notes were written — and then the release was called
off before anything was published, so the images and the bundle it names
below do not exist and no installation was ever upgraded to it. It is kept
as the record of what igni server held at this version, and because the
[changelog](../../CHANGELOG.md#060---2026-11-03) points at it.

The first release of igni server that has ever shipped is
[0.7.0](v0.7.0.md).

What this version held: the free, Apache-2.0 base of igni — sign-in,
organisations and roles, SCIM provisioning, SSO, the audit trail, inference
routing to the customer's own GPU nodes, the Helm chart and the admin
portal. Earlier development was not tagged; the changelog entry lists what
it holds, by area.

## What it would have given

| Artefact | Where | |
|---|---|---|
| API image | `ghcr.io/ignite-ember/igni-api:0.6.0` | never published |
| Portal image | `ghcr.io/ignite-ember/igni-portal:0.6.0` | never published |
| Helm chart | `charts/igni` (chart 0.1.0, appVersion 0.6.0) | in the repository |
| Offline bundle | `igni-bundle-0.6.0.tar`, for air-gapped installs | never sealed |

The bundle would have been signed with minisign, as it was then; it is
signed with cosign from 0.7.0 on. [OFFLINE_UPDATES.md](../OFFLINE_UPDATES.md)
is how to verify a bundle that exists.

## Highlights

- **Organisations are created, not given.** A super admin creates each
  organisation; a person belongs to one at a time, and each organisation
  has a database of its own, backed up on its own.
- **SSO and SCIM that hold up in practice.** OIDC sign-in lands on the
  portal page that finishes it, and SCIM deactivation is the portal's own
  deactivate and reactivate, in the audit trail with what the identity
  provider did and to whom.
- **Inference that does not waste GPU time.** A client that gives up stops
  its non-streamed completion upstream, a quiet upstream no longer ends a
  stream, and when every node is full requests wait their turn instead of
  failing.
- **Fleet's cloud pieces.** Apps, spaces, VM profiles and their requests,
  commands in VMs, events and the producer feed, for the paid Fleet module.
- **Supply chain.** Signed images with SBOMs, a signed offline bundle,
  every CI action pinned by SHA, a daily vulnerability scan that is green,
  and an OpenSSF Scorecard.

## Upgrading

Nothing upgrades to this version: it never shipped. An install made from an
untagged build of `main` upgrades to 0.7.0 instead — see
[0.7.0](v0.7.0.md).

## Security

This version fixes no advisory published against an earlier release; none
has been published. The image changes under **Security** in the changelog
were found by our own scans before release. To report a vulnerability, see
[SECURITY.md](../../SECURITY.md).
