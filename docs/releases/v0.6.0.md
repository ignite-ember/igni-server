# igni server 0.6.0

The first tagged release of igni server, the free, Apache-2.0 base of igni:
sign-in, organisations and roles, SCIM provisioning, SSO, the audit trail,
inference routing to the customer's own GPU nodes, the Helm chart and the
admin portal. Earlier development was not tagged; the
[changelog](../../CHANGELOG.md#060---2026-11-03) lists what this release
holds, by area.

## What you get

| Artefact | Where |
|---|---|
| API image | `ghcr.io/ignite-ember/igni-api:0.6.0` |
| Portal image | `ghcr.io/ignite-ember/igni-portal:0.6.0` |
| Helm chart | `charts/igni` (chart 0.1.0, appVersion 0.6.0) |
| Offline bundle | `igni-bundle-0.6.0.tar`, for air-gapped installs |

Each image is signed with the release cosign key and carries a CycloneDX
SBOM attestation. The offline bundle holds every image with its signature
and SBOM, the Helm chart and `igni-import`, under a MANIFEST signed with
minisign. [OFFLINE_UPDATES.md](../OFFLINE_UPDATES.md) is how to verify
either, and where the public keys are published.

## Highlights

- **Organisations are created, not given.** A super admin creates each
  organisation; a person belongs to one at a time, and each organisation
  has a database of its own, backed up on its own.
- **SSO and SCIM that hold up in practice.** OIDC sign-in lands on the
  portal page that finishes it, and SCIM deactivation is the portal's own
  deactivate and reactivate, in the audit trail with what the identity
  provider did and to whom.
- **Inference that does not waste GPU time.** A client that gives up stops
  its non-streamed completion upstream, a quiet upstream no longer ends a
  stream, and when every node is full requests wait their turn instead of
  failing.
- **Fleet's cloud pieces.** Apps, spaces, VM profiles and their requests,
  commands in VMs, events and the producer feed, for the paid Fleet module.
- **Supply chain.** Signed images with SBOMs, a signed offline bundle,
  every CI action pinned by SHA, a daily vulnerability scan that is green,
  and an OpenSSF Scorecard.

## Upgrading

There is no earlier tagged release to upgrade from. An install made from an
untagged build of `main` upgrades by moving its image tag to `0.6.0`;
the chart runs the database migrations as a `pre-upgrade` hook and stops
if they fail ([the chart's README](../../charts/igni/README.md#upgrades)).

## Security

This release fixes no advisory published against an earlier release; none
has been published. The image changes under **Security** in the changelog
were found by our own scans before release. To report a vulnerability, see
[SECURITY.md](../../SECURITY.md).

## Verifying

```sh
cosign verify --key igni-cosign.pub --insecure-ignore-tlog=true \
  ghcr.io/ignite-ember/igni-api:0.6.0
igni-import --bundle igni-bundle-0.6.0.tar --public-key igni-release.pub \
  --expect-version 0.6.0 --verify-only
```
