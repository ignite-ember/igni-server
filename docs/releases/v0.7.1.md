# igni server 0.7.1

The first release after 0.7.0. It changes no interface: every change is a
fix, an addition that keeps what it was, or a correction to what the
documentation said. It is the release the end-to-end campaign's findings
were fixed in.

## What you get

| Artefact | Where |
|---|---|
| API image | `ghcr.io/ignite-ember/igni-api:0.7.1` |
| Portal image | `ghcr.io/ignite-ember/igni-portal:0.7.1` |
| Helm chart | `charts/igni` (chart 0.2.1, appVersion 0.7.1) |
| Offline bundle | `igni-bundle-0.7.1.tar`, for air-gapped installs |

Each image is signed with the release cosign key and carries a CycloneDX
SBOM attestation. The offline bundle holds every image with its signature
and SBOM, the Helm chart and `igni-import`, under a MANIFEST signed with
the same cosign key — one key and one tool verify the whole bundle.
[OFFLINE_UPDATES.md](../OFFLINE_UPDATES.md) is how to verify either, and
where the public keys are published.

## Highlights

- **The scheduled scan now rescans the newest release's images.** The
  scheduled image scan is the only rescan a shipped image gets, and it
  rebuilt the default branch: when `main` moved dnspython to 2.9.2 the
  scan went green while the released 0.7.0 images still carried 2.9.1.
  The job checks out the newest `vX.Y.Z` tag and builds that, so a
  shipped image's CVEs are found rather than assumed fixed.
- **This release carries dnspython 2.9.2** (CVE-2026-128089), which the
  0.7.0 images did not.
- **A drained fleet answers 503, and a fleet with no nodes answers an
  empty model list.** Both were bare 500s, so a client could not tell a
  busy fleet from a broken one, and model discovery failed while the GPUs
  were off.
- **The Default group's seed reaches the API image.** `.dockerignore`'s
  `**/*.md` dropped the agent and skill seeds, so every organisation
  created on a released image got a Default group of 4 entries instead of
  20, while migrated ones got all of them.
- **The chart can mount files into the API pod**, so
  `INFERENCE_BACKENDS_PATH` — the case `app/config.py` calls the normal
  one — works from a file and not only from the inline
  `INFERENCE_BACKENDS`.
- **The production compose file lets a second igni run on the same
  host**, and the exit check's archive restores onto a plain PostgreSQL
  with no igni role in it.

The full list is the [changelog](../../CHANGELOG.md#071---2026-11-16).

## Upgrading

An install made from 0.7.0 upgrades by moving its image tag to `0.7.1`;
the chart runs the database migrations as a `pre-upgrade` hook and stops
if they fail ([the chart's
README](../../charts/igni/README.md#upgrades)).

Two things need a word before the upgrade.

- **The chart's own version is 0.2.1.** The chart changed — it mounts
  files into the API pod, and its Ingress now matches `/.well-known` as
  `ImplementationSpecific` so ingress-nginx admits it — so upgrading the
  chart is a minor bump of its own. It is deliberately independent of the
  application version: a customer taking a fixed template need not move
  the image.
- **A rollback needs the organisations' databases too.** Moving the
  shared plane back leaves the tenant template and every organisation at
  the newer head, and the next migrate stops at "Can't locate revision".
  `python -m app.db.sql.tenant_migrations --downgrade <revision>` (or
  `make downgrade-tenants REV=...`) takes them back; both steps are in
  the README and the chart README.

## Security

This release fixes CVE-2026-128089 in dnspython: the 0.7.0 images carry
2.9.1 and this one carries 2.9.2.

It also closes a race in sign-in. For up to two seconds after "sign out
everywhere" the withdrawal watermark — rounded up to the next second — was
at or after any new token's whole-second `iat`, so a sign-in answered 200
with a token that was refused on its first request, for ever. Sign-in now
waits until a token minted then postdates the watermark: at most about two
seconds, only right after a withdrawal, never to wait out clock skew.

The break-glass key now fails closed with a diagnosis. A
`SUPER_ADMIN_PASSWORD_HASH` that is not a bcrypt hash — the usual cause is
a compose env file interpolating the hash's `$` — answered every
break-glass call with a 500 (`ValueError: Invalid salt`). It answers 503
now, saying what the value is and that `$` must be written `$$` in a
compose env file.

No advisory has been published against an earlier release. To report a
vulnerability, see [SECURITY.md](../../SECURITY.md).

## Verifying

```sh
cosign verify --key igni-cosign.pub --insecure-ignore-tlog=true \
  ghcr.io/ignite-ember/igni-api:0.7.1
igni-import --bundle igni-bundle-0.7.1.tar --public-key cosign.pub \
  --expect-version 0.7.1 --verify-only
```
