# igni server 0.8.0

A security release. Two protections anchor it: a released image now trusts
only Ignite Ember's release key, whatever its settings, and the deployment
keeps its licence high-water mark in a tamper-evident central file so a
wound-back system clock no longer revives a lapsed licence. It is a minor,
not a patch, release because it also carries the server side of the
desktop app's Local / Cloud switch, which changes an interface — a person's
service events now go to one side (see the [changelog](../../CHANGELOG.md#080---2026-11-21)).

## What you get

| Artefact | Where |
|---|---|
| API image | `ghcr.io/ignite-ember/igni-api:0.8.0` |
| Portal image | `ghcr.io/ignite-ember/igni-portal:0.8.0` |
| Helm chart | `charts/igni` (chart 0.3.0, appVersion 0.8.0) |
| Offline bundle | `igni-bundle-0.8.0.tar`, for air-gapped installs |

Each image is signed with the release cosign key and carries a CycloneDX
SBOM attestation. The offline bundle holds every image with its signature
and SBOM, the Helm chart and `igni-import`, under a MANIFEST signed with
the same cosign key — one key and one tool verify the whole bundle.
[OFFLINE_UPDATES.md](../OFFLINE_UPDATES.md) is how to verify either, and
where the public keys are published.

## Highlights

- **A released image trusts only the release key, whatever its settings.**
  A release build writes a `RELEASE` marker beside
  `app/services/licence/keys.py`, and with it present no development key is
  read — whatever `APP_ENV` says, or a mount puts where a source checkout
  keeps its test keys. The test key `igni-test-1`, whose private half lives
  in every repository's test fixtures, is refused as `unknown_key` by every
  shipped image. `tools/licence/check_release_image.sh` runs the image with
  every development setting and the key file mounted and fails the release
  unless a test-key licence is refused, and the release workflow runs it
  before it publishes.
- **A central, tamper-evident licence clock.** The deployment holds one
  high-water mark — the latest time it has seen — in an encrypted, mode-0600
  integrity file under `IGNI_STATE_DIR`, seeded from the licence audit
  trail. A licence is evaluated as of no earlier than that mark, so winding
  the system clock back past `expires` on igni server, a module or the
  gateway no longer makes an expired licence valid again. Service clients
  and the gateway read the mark over `GET /v1/platform/licence/clock`
  rather than each keeping their own, so a clock wound back on any one of
  them is caught everywhere.
- **Tamper is caught and shown, admins only.** An integrity file that is
  missing, edited or replayed on a deployment with history is treated as
  tamper: the mark is taken from the audit trail, a tamper event is
  recorded, and a super admin sees a neutral `integrity` notice on `GET
  /v1/portal/licence`. The everybody banner says nothing. The detail stays
  in the file's event history and the sealed report.
- **A sealed licence-integrity report for Ignite Ember.** `POST
  /v1/portal/licence/integrity-report` (super admin, audited) exports the
  high-water mark, the tamper-event history, the licence id and per-module
  usage — no personal data — hybrid-encrypted so only Ignite Ember can open
  it. The former `licence_clock` database table and its migration are
  removed in favour of the file.

The full list is the [changelog](../../CHANGELOG.md#080---2026-11-21).

## Upgrading

An install made from 0.7.1 upgrades by moving its image tag to `0.8.0`;
the chart runs the database migrations as a `pre-upgrade` hook and stops if
they fail ([the chart's
README](../../charts/igni/README.md#upgrades)).

Three things need a word before the upgrade.

- **A writable, persisted state directory is now required.** The central
  licence clock keeps its sealed integrity file under `IGNI_STATE_DIR`
  (default `/var/lib/igni`), which must be a writable volume that survives
  a restart. The prod compose file mounts the `igni_state` volume there; on
  Kubernetes the chart provisions a PersistentVolumeClaim. **The default is
  a single API replica on a `ReadWriteOnce` volume**, which works on every
  cluster — including kind's local-path provisioner, which offers only
  `ReadWriteOnce` (the chart defaults `api.replicaCount: 1` and
  `state.persistence.accessMode: ReadWriteOnce`). **To run more than one API
  replica**, raise `api.replicaCount`, set `state.persistence.accessMode:
  ReadWriteMany` and point `state.persistence.storageClass` at an
  RWX-capable class, because every replica reads and writes the one mark. A
  fresh state directory is reseeded from the licence audit trail, so an
  upgrade loses nothing; it is only a new thing to back up (see [Data you
  own](../../README.md#data-you-own)).
- **The chart's own version is 0.3.0.** The chart changed — it provisions
  the state PVC and mounts it into the API pod — so upgrading the chart is a
  minor bump of its own, deliberately independent of the application
  version.
- **The sealed integrity-report export needs a key set.** `POST
  /v1/portal/licence/integrity-report` returns `503` until
  `INTEGRITY_REPORT_PUBLIC_KEY` is set to Ignite Ember's integrity-report
  public key. Nothing else depends on it, and the clock, the tamper notice
  and licensing all work without it; only the deliberate export to Ignite
  Ember does.

## Security

This release closes two ways a deployment could have run a licence it
should not have.

A released image trusted a development key when its settings asked it to;
anyone with the test key — whose private half ships in the repositories'
test fixtures — could sign a licence an image would accept. A release build
now carries a marker that refuses every development key, and the release is
checked against it before it is published.

A licence that had expired could be made valid again by winding the
system clock back. The deployment now evaluates a licence as of no earlier
than the central high-water mark, held in a tamper-evident file, and a mark
more than 24 hours ahead of the clock raises an admin-only warning.

No advisory has been published against an earlier release. To report a
vulnerability, see [SECURITY.md](../../SECURITY.md).

## Verifying

```sh
cosign verify --key igni-cosign.pub --insecure-ignore-tlog=true \
  ghcr.io/ignite-ember/igni-api:0.8.0
igni-import --bundle igni-bundle-0.8.0.tar --public-key cosign.pub \
  --expect-version 0.8.0 --verify-only
```
